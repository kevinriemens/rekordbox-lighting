| 2026-08-24 | TUI | Shared write layer | Pure refactor, no behaviour change, unblocking a TUI that calls the domain layer instead of shelling out to the CLI. The two-tier write model stopped being a convention and became visible at the call site: `safety.working_copy_write` (no guard, no backup — never touches live) versus `safety.write_transaction` (guard → backup → BEGIN → verify inside the transaction → commit), with `verify` now injectable per-operation so a macro write can assert its 25 rows while a file copy checks hashes. `preflight_restore` and `backup_live_databases` replace a duplicated guard sequence in `cli.py` and `sync.push` reaching into a private helper. Dry-run output is now built from frozen plan objects (`PushPlan`, `CreateMacroPlan`, `DeleteMacroPlan`) that carry `touches_live` and provably perform no write, rather than f-strings assembled next to the code that would do the writing. Research contradicted the story on three counts before any code: `sync.restore` doesn't exist (the duplication was in `cli.py`), the file was 772 lines not 643, and `push` can't route through `write_transaction` at all — it copies whole `.db3` files, there's no connection to transact on. One accepted compromise: the default verify is a no-op, because several frozen tests write deliberately corrupt non-SQLite bytes that a real integrity check would reject — the hook always fires, real checks are passed per-call. Primary gate held: 660 existing tests passed untouched. 683 tests. [Details](./completed/20260824-TUI-extract-shared-write-layer.md) |
| 2026-08-24 | CHORE | Remove the M1 test macros | `10007 AI TEST CLONE` and `10008 AI TEST SWEEP` are out of the live macro library; the six real user macros (10001-10006) are untouched. No code changed — this was the first end-to-end exercise of the shipped write path against live data on work the tool itself created: `pull` → two dry-runs → two `--write` deletes on the working copy → `push --write`. Before the live push, `user.db3` was swept for any column referencing either id (`macro_assign`, `phrase_data`, everything macro-id-shaped) — zero references, so no track or phrase row was orphaned. Verified after the fact by re-reading live: both ids gone, and zero leftover `macro_data` rows, confirming the delete cleans up all 25 slot rows rather than stranding them behind a removed parent. Backup at `backups/2026-08-24T115737300226Z`. One discrepancy with the backlog note: it recorded both macros as `enabled=1`, but the live read showed only 10005 and 10006 enabled — the test macros were dormant, so nothing that plays changed. `10002 TEST BAR` also looks like a leftover test macro but predates this tool and was left alone pending confirmation. |
| 2026-08-24 | CLI_COMPLETENESS | Pretty-print XML exports | Macro YAML exports now carry 2-space-indented XML matching rekordbox's own formatting, so an export can be diffed against rekordbox output and read by eye instead of parsed as a wall of text. Indentation is a reading concern and stays at the reading boundary: `macro_data.data` bytes are untouched, and no stored macro is reformatted. The scope addition that made it hold together was import-side canonicalization — without it, re-importing a hand-edited indented YAML would have written differently-formatted bytes than tool-generated macros, quietly breaking the diff-quiet invariant the story exists to protect. Empty slots stay empty strings, corrupt payloads pass through raw so an export never crashes on bad data, and capability validation still runs on the raw user input so errors quote what was actually written. One protected round-trip test had to move off a verbatim byte comparison: the shared fixture payload is itself hand-written pretty-printed XML, not canonical serializer output, so the old assertion was unsatisfiable under canonicalization — verified before accepting, scenario preserved. 659 tests. [Details](./completed/20260824-CLI_COMPLETENESS-pretty-print-xml-exports.md) |
| 2026-08-24 | CLI_COMPLETENESS | Macro discovery commands | The README no longer teaches users to bypass the CLI: `rbxlight macro list` (user macros by default, `--all`/`--factory` to widen), `macro search <term>` (factory content by default, `--user`/`--all`, SQL LIKE wildcards escaped so `%` and `_` match literally), and `macro show <id>` (metadata plus a programmed/empty verdict on all 25 fixture slots, `--yaml` for the full export) replace the three `python3 -c` one-liners in "Finding things" — the stale venue snippet among them, already served by `rbxlight venue list`. Query logic sits in `macros/repo.py` (`list_macros`, `search_macros`) so the planned TUI can import it without shelling out. Read-only end to end; conflicting flags rejected cleanly. Two test-contract deviations from the story (search default scope inverted, stray flag) were caught by reviewing assertions before implementation rather than after failures. 644 tests. [Details](./completed/20260824-CLI_COMPLETENESS-macro-discovery-commands.md) |
| 2026-08-16 | MULTI_VENUE | Truss editing in the visualizer | The truss stopped being a picture and became an editable object: select points, drag them (out-of-bounds accepted, not clamped), double-click a segment to insert, delete down to a two-point floor, nudge from the keyboard, and read the position and span in real centimetres — both views updating live. Plus `rbxlight layout install`, which ends the download-then-move-the-file chore with the usual dry-run diff and atomic write. The story was wrong on four counts, all caught before any code: the "recalibration hack to remove" had already been deleted last story, all six of its test names were invented (third story running), the browser export never carried truss geometry at all, and the browser had no centimetres to display in the first place. The bug that mattered was mine: the conversion note I handed the frontend omitted the 5% margin and the y-axis flip, so a ground-level (0,0) cm point round-tripped to (12,210) — meaning Download with *zero edits* would have silently exported a corrupted-but-well-formed polyline the CLI accepts happily. Caught by numeric audit, not by the suite. 577 tests. [Details](./completed/20260816-MULTI_VENUE-truss-editing-in-visualizer.md) |
| 2026-08-16 | MULTI_VENUE | Per-venue stage description | Truss geometry stopped being four constants and became saved per-venue data — a polyline of vertices in cm, with the normalization frame persisted alongside it. Fixture auto-placement generalized from "two verticals, two diagonals and a top" to segment-role classification over any polyline; the default arch reproduces its old output exactly, so all 18 existing placement tests passed untouched. Fixed the real bug underneath: truss and fixtures were normalized against two different bounding boxes, and the renderer carried a horizontal-stretch hack to hide it — that hack would have silently overridden any non-arch shape a user saved, so both the mismatch and the hack are gone. Also found a latent divide-by-zero that would have crashed the first flat truss. Story's file paths, storage format and all nine test names were wrong; corrected before any code was touched. 537 tests. [Details](./completed/20260816-MULTI_VENUE-per-venue-stage-description.md) |
| 2026-08-15 | MULTI_VENUE | Venue discovery and selection | `rbxlight venue list` (id, name, fixture count, `(active)` marker) plus one shared venue resolver for `preview` and `layout regenerate`. Research turned this from message-polish into a bug fix: `layout regenerate` never validated the venue at all, so a bad or stale `--venue` printed `0 fixture(s) unchanged.` and exited 0. Both commands now fail cleanly with the offending id and an enumeration of valid venues, distinguish an unset active pointer from a stale one, and state which venue they used and whether it came from the flag or the fallback. Also the first actionable "run pull first" guard on the read commands — previously a raw sqlite error. 502 tests. [Details](./completed/20260815-MULTI_VENUE-venue-discovery-and-selection.md) |

New `layout regenerate` fixes the stale-layout trap with a diff-first apply that resets algorithm-owned position/rotation but preserves user pan/tilt calibration. 476 tests. [Details](./completed/20260815-USER_CHANGE_REQUEST-cli-completeness.md) |
