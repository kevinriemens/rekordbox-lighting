| 2026-08-24 | TUI | Interactive menu | New terminal menu for `rbxlight`, at feature parity with the CLI including writes. Accessible via `rbxlight` (no args) or `rbxlight tui`. Implements a two-tier confirmation model: working-copy actions (macro create/delete, layout regenerate/install, sync pull) use ordinary `confirm(default=False)`; live actions (sync push, backups restore) use distinct danger rendering with typed confirmation. Built as a new flat `src/rbxlight/menu/` package (1030 lines across 13 modules) calling the domain layer directly, with 62 new tests in `tests/tui/`. All 719 pre-existing tests passed unmodified. 781 tests. [Details](./completed/20260824-TUI-interactive-menu.md) |
| 2026-08-24 | BUGS | Ship margin fraction in preview payload | The 5% normalization margin existed twice — a Python constant and a hardcoded JS literal — linked by nothing but a comment saying "keep these in sync". Change one and `normToCm()` silently returns wrong centimetres into the truss panel and the exported `structure_cm`: no crash, no failing test. Same defect class that shipped a (0,0)cm → (12,210)cm round-trip error in the 2026-08-16 truss-editing story, which is why it was worth an S rather than a comment. The constant is now public (`MARGIN_FRACTION`), travels in the payload as `margin_fraction`, and the template reads it from there. Deliberately no JS fallback: a missing key means the payload and template are different versions, and defaulting to 0.05 would rebuild the exact silent-corruption path being removed, so the guard throws instead. The payload-shape tripwire test was updated rather than weakened — its key-set literal grew by one and stayed a strict `==`. Honest limit: with no JS test runner, only the Python half is machine-verified; the template change is code-review-only, which is acceptable here because the transform maths was untouched and only the provenance of `m` changed. 719 tests. [Details](./completed/20260824-BUGS-ship-margin-fraction-in-preview-payload.md) |
| 2026-08-24 | REFACTOR | Split `preview/layout.py` | The project's largest file — 955 lines, five mixed concerns — became four flat siblings (`layout_geometry` ← `layout_segments` ← `layout_placement` ← `layout_io`) behind a 97-line pure re-export facade. Strict one-directional imports, `generate_layout` kept whole. The whole safety argument was that no caller and no test reaches past the public surface today, a property that would not survive indefinitely: 717 tests passed completely unmodified. Architecture skill amended — flat means no nested sub-packages, not never split a file — superseding the 2026-08-16 decision that declined this split because the rule had no upper bound. [Details](./completed/20260824-REFACTOR-split-preview-layout-module.md) |
| 2026-08-24 | TUI | Shared orchestration layer | Second pure refactor unblocking the TUI, and it only exists because research contradicted the story that triggered it. `/build TUI-interactive-menu` assumed the domain layer was directly callable now that the write layer had landed; it wasn't. Four things the menu needs lived nowhere but inside `cli.py` — venue resolution (explicit id vs active pointer vs *stale* pointer), the `layout regenerate` and `layout install` orchestrations, and the four-call preview pipeline — and the TUI is forbidden to import `cli.py`. Building it as specified would have reimplemented all four as a second write path drifting from the CLI, the exact failure the previous story was written to prevent. Offered the choice, the user split the extraction into its own story and built it first. New typer-free `orchestration.py`: venue resolution now raises three distinct exception types (not-found / no-active / stale-active) instead of exiting, each carrying the venue list for the error message, and regenerate/install/preview are each callable as one unit. Four new zero-write plan objects (`PullPlan`, `RestorePlan`, `LayoutRegeneratePlan`, `LayoutInstallPlan`) join the existing three; the first two are deliberately not wired into `cli.py`, because doing so would change `pull`/`restore` dry-run output and byte-identical behaviour was the acceptance gate. The conflict scan is what made that gate safe to promise: no test anywhere reaches into a `cli` private helper, so all 683 existing tests were frozen and passed untouched. It also surfaced the constraint that mattered most — location constants must be read at call time, since an import-time binding would silently defeat ~23 monkeypatches and point the suite at the user's real rekordbox data. A naming defect was caught at the review gate rather than shipped: the test contract's `missing_fixture_ids` meant venue-fixtures-absent-from-the-file, while the CLI's frozen "no longer patched" warning meant the opposite direction, so the plan couldn't feed the CLI's own confirmation gate and the TUI would have hit it immediately; now split into two unambiguously-named fields. Honest result on the stated goal: `cli.py` only lost 48 lines, because plan construction moved in as orchestration moved out — the optimizer reviewed for more and correctly declined, since what remains is either presentation or bound to `typer.echo`. 717 tests. [Details](./completed/20260824-TUI-extract-actions-layer.md) |
| 2026-08-24 | TUI | Shared write layer | Pure refactor, no behaviour change, unblocking a TUI that calls the domain layer instead of shelling out to the CLI. The two-tier write model stopped being a convention and became visible at the call site: `safety.working_copy_write` (no guard, no backup — never touches live) versus `safety.write_transaction` (guard → backup → BEGIN → verify inside the transaction → commit), with `verify` now injectable per-operation so a macro write can assert its 25 rows while a file copy checks hashes. `preflight_restore` and `backup_live_databases` replace a duplicated guard sequence in `cli.py` and `sync.push` reaching into a private helper. Dry-run output is now built from frozen plan objects (`PushPlan`, `CreateMacroPlan`, `DeleteMacroPlan`) that carry `touches_live` and provably perform no write, rather than f-strings assembled next to the code that would do the writing. Research contradicted the story on three counts before any code: `sync.restore` doesn't exist (the duplication was in `cli.py`), the file was 772 lines not 643, and `push` can't route through `write_transaction` at all — it copies whole `.db3` files, there's no connection to transact on. One accepted compromise: the default verify is a no-op, because several frozen tests write deliberately corrupt non-SQLite bytes that a real integrity check would reject — the hook always fires, real checks are passed per-call. Primary gate held: 660 existing tests passed untouched. 683 tests. [Details](./completed/20260824-TUI-extract-shared-write-layer.md) |
| 2026-08-24 | CHORE | Remove the M1 test macros | `10007 AI TEST CLONE` and `10008 AI TEST SWEEP` are out of the live macro library; the six real user macros (10001-10006) are untouched. No code changed — this was the first end-to-end exercise of the shipped write path against live data on work the tool itself created: `pull` → two dry-runs → two `--write` deletes on the working copy → `push --write`. Before the live push, `user.db3` was swept for any column referencing either id (`macro_assign`, `phrase_data`, everything macro-id-shaped) — zero references, so no track or phrase row was orphaned. Verified after the fact by re-reading live: both ids gone, and zero leftover `macro_data` rows, confirming the delete cleans up all 25 slot rows rather than stranding them behind a removed parent. Backup at `backups/2026-08-24T115737300226Z`. One discrepancy with the backlog note: it recorded both macros as `enabled=1`, but the live read showed only 10005 and 10006 enabled — the test macros were dormant, so nothing that plays changed. `10002 TEST BAR` also looks like a leftover test macro but predates this tool and was left alone pending confirmation. |
| 2026-08-24 | CLI_COMPLETENESS | Pretty-print XML exports | Macro YAML exports now carry 2-space-indented XML matching rekordbox's own formatting, so an export can be diffed against rekordbox output and read by eye instead of parsed as a wall of text. Indentation is a reading concern and stays at the reading boundary: `macro_data.data` bytes are untouched, and no stored macro is reformatted. The scope addition that made it hold together was import-side canonicalization — without it, re-importing a hand-edited indented YAML would have written differently-formatted bytes than tool-generated macros, quietly breaking the diff-quiet invariant the story exists to protect. Empty slots stay empty strings, corrupt payloads pass through raw so an export never crashes on bad data, and capability validation still runs on the raw user input so errors quote what was actually written. One protected round-trip test had to move off a verbatim byte comparison: the shared fixture payload is itself hand-written pretty-printed XML, not canonical serializer output, so the old assertion was unsatisfiable under canonicalization — verified before accepting, scenario preserved. 659 tests. [Details](./completed/20260824-CLI_COMPLETENESS-pretty-print-xml-exports.md) |

| 2026-08-16 | MULTI_VENUE | Truss editing in the visualizer | The truss stopped being a picture and became an editable object: select points, drag them (out-of-bounds accepted, not clamped), double-click a segment to insert, delete down to a two-point floor, nudge from the keyboard, and read the position and span in real centimetres — both views updating live. Plus `rbxlight layout install`, which ends the download-then-move-the-file chore with the usual dry-run diff and atomic write. The story was wrong on four counts, all caught before any code: the "recalibration hack to remove" had already been deleted last story, all six of its test names were invented (third story running), the browser export never carried truss geometry at all, and the browser had no centimetres to display in the first place. The bug that mattered was mine: the conversion note I handed the frontend omitted the 5% margin and the y-axis flip, so a ground-level (0,0) cm point round-tripped to (12,210) — meaning Download with *zero edits* would have silently exported a corrupted-but-well-formed polyline the CLI accepts happily. Caught by numeric audit, not by the suite. 577 tests. [Details](./completed/20260816-MULTI_VENUE-truss-editing-in-visualizer.md) |
| 2026-08-16 | MULTI_VENUE | Per-venue stage description | Truss geometry stopped being four constants and became saved per-venue data — a polyline of vertices in cm, with the normalization frame persisted alongside it.
